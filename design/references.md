# 引用与编译

本文件拥有引用的语法、目标种类与解析器、截取表达式、编译的规则和错误，以及文档取回表与预览。术语定义见 [README.md §定义](README.md#定义)。Launch 如何使用编译结果归 [launch-events.md](launch-events.md)。输入：块、引用、编译的定义；约束"只做确定性截取"。

## 1. 语法

- 一个引用是 `((` 目标 `))`，或 `((` 目标 ` | ` 截取表达式 `))`。
- 目标是一个块 id、一个块结果（`<块 id>.result`）、一个 GitHub issue 或 PR 的 URL，或一个 `file:` 路径（§2）。
- 位于围栏代码块或行内代码中的 `((…))` 不是引用，是文本。因为编排块的代码可能含有这种字符序列。
- 不含 `|` 的引用使用该目标种类的默认截取（§3）。
- 写在引用之外的 URL 是文本，不展开。因为人写链接不一定想把内容放进 prompt。

理由：`((…))` 在 Tern 的 `md` 节点中原样显示（[E1.2](appendix-evidence.md#e12-表单块的点击与焦点事件)），因此块正文的渲染视图中能看到引用本身；它的展开文本显示在块正文之后（§5）。
替代：`[[目标|截取表达式]]`。不选，因为 Obsidian 等工具会把它当作 wiki 链接改写。

## 2. 目标种类与解析器

目标种类是闭合列举。解析器按目标种类取回一个结构化值：

| 目标种类 | 目标形式 | 解析器取回的值 |
|---|---|---|
| 块 | `b<正整数>` | 该块的块正文，递归编译之后的结果 |
| 块结果 | `b<正整数>.result` | 同一 Run 中关于该块、`kind` 为 `result` 的最近一条记录的文本（[runs.md §4](runs.md#4-记录)）。只能在 Run 中使用 |
| GitHub issue | `https://github.com/<owner>/<repo>/issues/<n>` | `{title, body, comments: [{author, created_at, body}]}`，经 `gh api` 取回（K3） |
| GitHub PR | `https://github.com/<owner>/<repo>/pull/<n>` | 同 issue；`comments` 只含会话评论 |
| 本地文件 | `file:<相对模板文件所在目录的路径>` | 文件文本。Run 中的 `file:` 引用同样相对模板文件所在目录，因为 Run 文件位于另一个目录，而块正文从模板原样复制（[runs.md §1](runs.md#1-模板与-run)） |

- 其他目标都是错误 `UnknownTarget`。
- 块与块结果以外的目标种类称为外部目标。
- 解析器不得调用 LLM。

## 3. 截取表达式

截取表达式是逗号分隔的选择器列表。展开文本按列表顺序拼接各选择器的结果，相邻结果之间隔一个空行。

| 目标种类 | 选择器 | 结果 | 默认（不写表达式） |
|---|---|---|---|
| 块、块结果、本地文件 | `lines(a..b)` | 第 a 到第 b 行，含两端，从 1 计 | 全文 |
| 块、块结果、本地文件 | `section("标题")` | 标题文本完全相等的 Markdown 标题下的内容，到下一个同级或更高级标题为止 | |
| issue、PR | `title` | 标题 | `title, body, comments` |
| issue、PR | `body` | 正文 | |
| issue、PR | `comments` | 全部评论，按时间顺序 | |
| issue、PR | `comments(-n)` | 最后 n 条评论 | |
| issue、PR | `comments(a..b)` | 第 a 到第 b 条评论，从 1 计 | |

- 选择器对目标种类无效，或参数越界，都是错误 `BadExpression`。
- 每条评论展开为 `@<author> <created_at>:` 一行，后接评论正文。

## 4. 编译

- 输入：一个有序的块 id 列表，一份外部取回表（外部目标 → 取回结果与取回时间，或取回失败），以及一份块结果表（块 id → 最近一条 `result` 记录的文本、时间、条目序号、写入者与 `launch`）。块结果表由文档服务在编译之前从所属 Run 的时间线中读出。
- 编译之前，文档服务为这组块引用到、但取回表中没有的外部目标各取回一次，并把结果或失败加入取回表。取回表中已有的目标不重新取回。因此编译时，每个被引用的外部目标都在取回表中。
- 编译按列表顺序编译每个块，块与块之间隔一个空行。
- 块引用：用被引用块的编译结果替换引用，再应用截取表达式。
- 块结果引用：用块结果表中的文本应用截取表达式。块结果是人或协调者写入的记录，是可信内容，不加边界。
- 外部引用：用取回表中的结果应用截取表达式，再用下面的边界包起来：
  ```text
  <external source="<目标>" fetched="<ISO 8601 时间>">
  <展开文本>
  </external>
  ```
  因为 R10。块正文是可信内容，不加边界。
- 引用深度从被编译的块计起，深度超过 8 是错误 `TooDeep`。
- 引用路径中再次出现同一块 id 是错误 `Cycle`。
- 编译输出 `CompileResult`：

  | 变体 | 内容 |
  |---|---|
  | `Ok` | `text`；`sources`：每个引用的目标、截取表达式，以及外部目标的取回时间或块结果的记录序号、写入者与 `launch`，按出现顺序 |
  | `Err` | 下列错误之一，附出错位置：引用所在块 id 与引用文本 |

- 错误是闭合列举：

  | 错误 | 触发条件 |
  |---|---|
  | `UnknownBlock` | 块 id 不存在于文档中 |
  | `UnknownTarget` | 目标不属于 §2 的种类 |
  | `BadExpression` | 截取表达式不能解析，或违反 §3 |
  | `Cycle` | 引用路径成环，附路径 |
  | `TooDeep` | 深度超过 8 |
  | `NoResult` | 块结果引用的块在所属 Run 中没有 `result` 记录，或引用写在模板中 |
  | `FetchFailed` | 取回表中该目标记为取回失败：`gh` 非零退出或超时（附退出码与错误输出），或本地文件不存在或不可读（附系统错误） |

- 编译输出 `Err` 时，文档服务不得创建 Launch。
- 编译是一个纯函数：它的输入是块正文、取回表和块结果表，不读取时钟、网络或文件。取回与读取块结果发生在编译之前，由文档服务完成。因为 I3。

## 5. 文档取回表与预览

- 文档服务持有一份文档取回表：外部目标 → 取回结果与取回时间，或取回失败。预览、引用展开视图、块检查（[checks.md](checks.md)）、`inspect` 与 `launch` 都以它为编译输入，并按 §4 补取缺少的目标。因为同一个外部目标在文档中只应有一份当前内容。
- 表中已有的目标只在两种情况下重新取回：人在块卡片中对一个引用执行"重新取回"；协调者调用 K1 的 `refetch`。重新取回替换表中该目标的结果。文档服务不自动重新取回（R7）。
- 文档取回表不持久化；文档服务重启后为空。Launch 在创建时复制它需要的部分（[launch-events.md §1](launch-events.md#1-launch)）。
- 文档服务为任一组块显示编译预览，内容与 `Ok.text` 逐字节相同，附字符数。预览与随后对同一有序块列表的 `launch` 读取同一份文档取回表与块结果表；两次操作之间，这组块的依赖闭包中块正文不变、用到的外部目标没有重新取回、引用的块结果没有新的 `result` 记录时，两者逐字节相同。因为 R3、Q2。
- 渲染视图展开引用：块正文的渲染视图之后，块正文中的每个引用按出现顺序各显示一个可折叠的 `section` 节点，初始为展开。它的标题是引用文本，外部目标另附取回时间或"取回失败"；它的内容是按 §4 的规则替换这一个引用得到的文本（外部目标含边界标记），由同一个编译函数生成，以 `md` 节点显示；出错时内容为 §4 的错误。因为需求来源要求引用在渲染时展开，人不打开预览也能看到块将带入 prompt 的内容。取回失败或被引用的内容很长时，人可以折叠它；折叠只改变界面状态，不改变文档（[E1.5](appendix-evidence.md#e15-可折叠的-section-节点)）。
- 渲染视图中出现取回表中没有的外部目标时，文档服务按 §4 取回一次，取回期间该 `section` 的标题附"取回中"。这与编译之前的补取是同一条规则：一个外部目标只在首次被引用或显式重新取回时取回。
